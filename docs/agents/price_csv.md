# Цена (строки), CSV, превью (Агент 8, бэклог п. 11, 12, 14)

Дата: 2026-11-07. Владелец: `app/static/js/editor.js` (только price/csv часть),
`app/static/js/projects.js` (превью), `app/static/js/cutlist_csv.js` (новый).
Не тронуты: `scene.js`, `ai.py`, `generators/`.

## Что сделано

### 1. Строки цены `price.lines` — материал/работа/доставка (`editor.js`, ТЗ п. 11, бэклог п. 14)
- Цена остаётся ручной заглушкой: автоматических расчётов нет (до прайса цеха).
- При загрузке/применении ИИ-проекта пустые `lines: []` разворачиваются в 3 строки
  `Материал / Работа / Доставка` с `amount: null` (`ensurePriceLines`, `defaultPriceLines`).
  Свои строки и старые проекты не ломаются: битые записи выравниваются
  (нет названия → «Строка», сумма не число → `null`).
- UI в панели «Экспорт для клиента» (внутри `renderExport`, без правок `index.html`):
  каждая строка — поле названия + поле суммы KZT + кнопка `✕` (последнюю удалить нельзя),
  «+ Строка» добавляет свободную, подпись «Сумма строк: N KZT»,
  кнопка «Итого из строк → в «Цена»» подставляет сумму в `price.total`.
- Кнопки только на `onchange` (не на каждое нажатие) — фокус не теряется, `scheduleSave()` сохраняет.
- Существующее поле «Цена, KZT» и чекбокс «Цена клиенту» сохранены как были.

### 2. Выгрузка деталировки в CSV (`app/static/js/cutlist_csv.js` + кнопка, бэклог п. 11, ТЗ п. 7.3)
- Новый модуль без DOM на верхнем уровне (чистые функции работают в node):
  `getCutRows(project)` сводит детали всех предметов через `buildItemByType` + `summarizeCut`
  (группировка `name|a|b`, как в таблице редактора; битый тип — пропуск, а не падение),
  `toCsv()/csvCell()/fmtNum()`, `buildCutCsv(project)`, `downloadCutCsv(project)`.
- Формат: разделитель `;`, CRLF, BOM `\uFEFF` (Excel открывает кириллицу сразу),
  заголовок `Деталь;Длина, мм;Ширина, мм;Кол-во;Тип;Площадь, м2`,
  строка «Итого;ДСП 16 мм: N дет., X м2» по толщинам. Кавычки удваиваются по CSV.
- Кнопка «Скачать деталировку CSV» добавляется в панель «Деталировка» после `#cut-sum`
  один раз в `renderCut()` (идемпотентна, без дублей при перерисовке).
  Файл: `<id>-cutlist.csv`. Статус «CSV скачан: N строк (файл)» в `#save-status`.

### 3. Миниатюра проекта в карточке (`projects.js`, ТЗ п. 9, бэклог п. 12)
- Превью хранится **только в `localStorage`** (`mebel3d-thumb:<id>`), **не в `project.json`**.
- Снимается с живого канваса редактора (`#view canvas`, `preserveDrawingBuffer: true` уже есть):
  `captureCanvasThumb()` уменьшает до 480px шириной, JPEG 0.75 (~15–30 КБ).
- Автосохранение без правок `scene.js`/`main.js`: пока открыт редактор — тик каждые 5 с,
  сохраняем раз в 20 с; при уходе на список (`hashchange` → `#/`) и перед `renderProjects()`
  снимаем последний кадр сразу. Неудачная запись при переполнении квоты пробуется
  меньше (240px, 0.55) и не затирает старое превью.
- Карточка: `<img class="lib-photo thumb-preview">` (использует существующий `.lib-photo`
  из `style.css`, без новых CSS). Нет превью — картинка скрыта (`display:none`),
  заголовка не сломана; тултип подсказывает «откройте проект — превью сохранится».
- Удаление проекта очищает превью (`clearThumb`), «Копия» копирует превью
  (`copyThumb`), переименование id не меняет — превью остаётся.

## Осталось/замечания

- Браузерная приёмка вживую не пройдена: открыть проект → подождать 20 с →
  «Проекты» → карточка с превью; поле цены ввести → «+ Строка», «Итого из строк»;
  кнопка CSV → файл открывается в Excel без кракозябр.
- Отдельная CSS-строка для `.thumb-preview` не добавлялась (вне владения):
  используется существующий `.lib-photo`. При желании можно вынести в `style.css`.
- Схема `app/schema.py` не менялась: текущая валидация `price` пропускает `lines`
  с произвольным содержимым (проверяет только `total`), сохранения проходят.
  Строгая валидация строк (`lines[]: {name: str, amount: num|null}`) — кандидат
  для отдельной задачи вместе со строковой частью `schema.py`.
