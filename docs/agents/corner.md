## Какие формулы

Основа — два вызова `buildItem` с `type='kitchen_base', top=false`; формулы корпуса
(боковины `t × bodyH × (D−4)`, ХДФ 4 мм, цоколь, полки, фасады с зазором 3 мм,
ящики с зазором 13 мм и выездом 70%) берутся из `corpus.js` без изменений.

- **Ряд A (низ вдоль X)**: локальные координаты corpus `(lx, lz)` → глобальные `(lx, lz + D/2)`.
  Занимает `x 0..lenA, z 0..D`, фасад в `+z`.
- **Ряд B (низ вдоль Z, поворот 90°)**: поворот `rotY +90°`: `(lx, lz) → (lz, −lx)`,
  затем сдвиг `(D/2, D+lenB)`: `gx = lz + D/2`, `gz = D + lenB − lx`. Размер детали
  `[sx, sy, sz] → [sz, sy, sx]`. Занимает `x 0..D, z D..D+lenB`, фасад в `+x`
  (вглубь кухни). Угловой квадрат `x 0..D, z 0..D` принадлежит ряду A — детали
  не дублируются (боковин ровно `2×(modulesA+modulesB)`).
- **Детали групп** (фасад/ручка относительно pivot) поворачиваются вокруг своего
  pivot (`(ox, oz) → (oz, −ox)`), а не сдвигаются — иначе двери/ящики оторвутся
  от шарниров. Pivot'ы в `anim` трансформируются как глобальные точки.
- **Столешница 38 мм, свес 30 мм** (как в corpus.js): две плиты, стык без перекрытия.
  Плита A: `lenA × (D+30)`, `pos = [lenA/2, H+19, D/2+15]` (впритык к задней стене,
  свес спереди). Плита B: `(lenB−30) × (D+30)`, `pos = [(D+30)/2, H+19, D+30+(lenB−30)/2]` —
  начинается с `z = D+30`, где заканчивается свес плиты A, заканчивается впритык
  к концу ряда B. Угловой квадрат накрыт один раз (плитой A).
- **Габариты**: `dims = { w: max(lenA, D), h: H, d: max(D+lenB, D), lift: 0, lenA, lenB }`
  (по умолчанию `1800 × 720 × 1760` при `modulesA=3, modulesB=2, модуль 600, D=560`).
- **Параметры** (все необязательные): `t=16`, `w`/`moduleW=600`, `h=720`, `d=560`,
  `plinth=100`, `modulesA`/`modules=3`, `modulesB=2`, `shelves=1`,
  `front='door1'` (`frontA`/`frontB` отдельно), `drawers=3` (`drawersA`/`drawersB`),
  `top=true`, `handle='bar160'`; остальные поля прокидываются в `buildItem` как есть.
  `modulesB=0` даёт один ряд, `top=false` — без столешницы.

## Найденный дефект corpus.js (исправлен только в своём файле)

`corpus.js` выдаёт одинаковый `id` двери/ящика в каждом модуле (`door0` в трёх
модулях). `scene.js` группирует детали по этому id — без дедупликации все двери
ряда сели бы на первый pivot. `buildCorner` делает id уникальными по порядку
появления (`A:door0#0`, `A:door0#1`, …) и добавляет префикс ряда (`A:`/`B:`).
Это исправляет отображение и для обычных много-модульных рядов при интеграции —
рекомендую тот же приём в `buildItem`/`scene.js` отдельной задачей.

## Как интегрировать (не делал по заданию)

1. **Тип в проекте**: новый `type` (например `kitchen_corner`) в `app/schema.py` +
   пресет в `common.js` + запись в `GENERATORS` (`index.js`): `kitchen_corner: buildCorner`
   (обёртка при необходимости через `withDefaults`-аналог: у `buildCorner` свои
   дефолты, `withDefaults` не нужен).
2. **Панель редактора** (`editor.js`): поля `modulesA`, `modulesB` (или `modules`
   для ряда A), остальные — как у `kitchen_base`.
3. **Экспортёр** (`app/exporter.py`): включить `corner.js` в бандл (он импортирует
   `corpus.js` — тот уже в бандле).
4. **Ящики ряда B в сцене**: `scene.js` (`applyOpen`) сдвигает pivot ящика строго
   по `+z`, поэтому ящики ряда B визуально уезжают на юг вместо востока.
   Двери ряда B (поворот вокруг Y) открываются корректно с тем же знаком.
   Фикс: добавить в `anim.drawers` ось (`axis: 'x'` для ряда B) и в `scene.js`
   сдвигать pivot по этой оси (`pivot.position[axis] = travel * MM * openT`).
   Данные для этого уже есть: у ящиков ряда B `pivot` лежит в полосе `x 0..D`.
