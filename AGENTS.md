# AGENTS.md — точка входа для ИИ-агента в проекте «Мебель 3D»

Прочитай этот файл целиком, затем `docs/HISTORY.md` (история и текущее состояние)
и `TZ_mebel3d.md` (техзадание — источник истины по требованиям).

## Что это за проект

Локальное приложение для Windows: конструктор 3D-презентаций корпусной мебели.
Оператор (бывший сотрудник мебельного цеха) собирает проект мебели в редакторе,
сохраняет его и отдаёт клиенту. Полные требования — в `TZ_mebel3d.md`, работа идёт
этапами (7 этапов, этапы 1–5 завершены, следующий — этап 6: новые типы мебели).
Бэклог на доработку после этапов 6–7 — в `docs/HISTORY.md`, раздел «Бэклог».

## Стек и ограничения

- Python 3.11+ в `.venv` (создаётся `start.bat`), FastAPI + uvicorn. Зависимости: `requirements.txt` (fastapi, uvicorn — больше ничего).
- three.js **v0.180.0 локально** в `app/static/vendor/three/` (`three.module.js` + `three.core.js`). CDN запрещён ТЗ.
- Фронтенд — нативные ES-модули, **без сборки** (no bundler, no npm build). `package.json` существует только для `"type": "module"`, чтобы node понимал ES-модули в тестах.
- Всё работает офлайн на `http://127.0.0.1:8765`.
- Проекты хранятся в `data/<id>/project.json` — по папке на проект. `data/` не в коде: код обновляем, проекты не трогаем.

## Команды

```
start.bat                                  — запуск (первый раз создаёт .venv и ставит зависимости)
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8765   — запуск вручную
.venv\Scripts\python.exe -m pytest tests -q                     — тесты валидации (Python)
node tests\test_generators.mjs                                  — тесты генераторов (node)
node tests\test_room.mjs                                        — тесты комнаты (node)
npm install three@0.180.0 --no-save --prefix .sharrowkin/tmp3d   — если нужно снова скачать three.js
```

Windows, cmd.exe: цепочки через `&&`, кавычки только двойные, многострочный код —
писать в файл `.sharrowkin/scripts/*.py` и запускать, не через `python -c`.

## Правила, которые нельзя нарушать

- **Формулы конструкции — только в `generators/`.** Сцена строит меши из готовых
  деталей (`parts`), сама ничего не считает.
- Единицы: размеры в мм, модель в метрах (`MM = 0.001`).
- Ошибки валидации — списки строк **по-русски** (их видит Оператор и ИИ на повторе, этап 4).
- `id` проекта = имя папки в `data/`; `save()` перезаписывает `data.id` именем папки.
- Новый проект сохраняется без валидации «хотя бы один item» (проект пуст по определению);
  `save()` валидирует всегда и отдаёт 400 со списком ошибок.
- Цена — заглушка (ТЗ): никаких реальных расчётов стоимости, пока цех не даст прайс.
- Комментарии и тексты интерфейса — по-русски.
- Не добавлять CDN, сборщики, новые зависимости без причины.

## Формат project.json (v1)

Проект: `{version:1, id, name, client, notes, room, items[], price}`.
Предмет: `{id, type, position:{x,z}, rotationY, w, h, d, t(16|18), plinth, lift,
modules, shelves, front(open|door1|doors2|drawers), drawers, top, corpus, facade, handle}`.
Диапазоны и типы — в `app/schema.py`, они же в `RANGE`/`PRESETS` в `generators/common.js`.
Пример рабочего проекта: `data/demo/project.json`.
