# Мебель 3D

Локальный конструктор 3D-презентаций корпусной мебели. Оператор собирает проект
(шкаф, тумба, кухня низ/верх) в браузере, видит деталейку раскроя ДСП и
сохраняет проект у себя на ПК. Работает без интернета.

> Текущий этап — **этап 5 (библиотека) завершён** по `TZ_mebel3d.md`:
> декоры, ручки и примеры цеха с загрузкой по фото/тексту, использование
> в проектах, экспорте и как контекст ИИ. Следующий — этап 6 (новые типы
> мебели). Полный список того, что ещё не начато, — раздел «Бэклог»
> в `docs/HISTORY.md`.

## Запуск

Требуется Windows и Python 3.11+.

1. Распакуйте папку проекта.
2. Дважды щёлкните **`start.bat`**. Первый запуск сам создаст окружение
   `.venv` и поставит зависимости (`fastapi`, `uvicorn`), затем откроет браузер
   на `http://127.0.0.1:8765`.
3. Вручную то же самое:
   `".venv\Scripts\python.exe" -m uvicorn app.main:app --host 127.0.0.1 --port 8765`

Проекты хранятся в папке `data/<id>/project.json` — код можно обновлять,
проекты не потеряются. Папка `data/` в git не попадает (`.gitignore`).

Готовый пример: откройте проект **«Демо-кухня»** (`# /project/demo`) —
кухня 3+3 модуля, она же в `data/demo/project.json`.

## Структура

```
app/main.py            FastAPI: API проектов + экспорт + ИИ + статика
app/projects.py        Хранение в data/, транслит кириллицы в id
app/schema.py          Валидация project.json (ошибки по-русски)
app/exporter.py        Сборка автономного HTML для клиента (этап 3)
app/ai.py              ИИ: OpenAI-совместимый провайдер, валидация, повтор, лог
app/settings.py        Настройки ИИ в data/settings.json (ключ только локально)
app/ai_rules.md        Правила цеха для системного промпта (редактируемый файл)
app/library.py         библиотека: декоры, ручки, примеры (data/library/)
app/static/js/library.js  экран «Библиотека»: вкладки, фото, добавление/удаление
app/static/js/ai.js       панель «ИИ-чат»: настройки, три кнопки, карточки вариантов
app/static/index.html  Экраны: список проектов / редактор
app/static/js/main.js        Точка входа, hash-маршрутизация, тема, кнопки сцены
app/static/js/projects.js    Список проектов
app/static/js/editor.js      Состояние, панели, undo/redo, автосохранение, комната
app/static/js/scene.js       three.js: меши, комната, орбита, перетаскивание, скриншот
app/static/js/room.js        Комната: параметры, текстуры, спецификация (без three.js)
app/static/js/export-client.js  Клиентский просмотрщик для экспортного HTML (без редактора)
app/static/js/generators/    Формулы конструкции (только здесь!)
  common.js   константы: MM, SHEET, COLORS, RANGE, COUNTS, PRESETS
  corpus.js   buildItem: детали одного предмета
  index.js    buildItemByType для 4 типов
  cutlist.js  summarizeCut: деталировка, площадь ДСП, листы 2750×1830 +15%
tests/   pytest (валидация + хранение + экспорт + ИИ + библиотека) и node (генераторы = формулы прототипа, комната)
mebel3d.html   Эталонный прототип — формулы не менять
```

## Как добавить новый тип мебели

1. Добавьте пресет в `PRESETS` в `generators/common.js` и тип в `TYPES` в
   `app/schema.py` (а также диапазоны, если нужны новые поля).
2. Реализуйте генератор: функция `build(params) → { parts, anim, dims }` в
   отдельном файле рядом с `corpus.js` (или общая логика в `corpus.js`, как сейчас
   у всех 4 типов). Детали — это записи `{ name, kind, cut, size, pos, material,
   group }`; анимация — `{ id, pivot, sign, angle }` для дверей и `{ id, pivot,
   travel }` для ящиков.
3. Зарегистрируйте в `app/static/js/generators/index.js` (`GENERATORS`) и
   экспорт в `buildWardrobe`/`buildChest`/…-стиле.
4. Добавьте кнопку в `index.html` (`#add-row`) и тесты деталировки в
   `tests/test_generators.mjs`, сверяясь с прототипом.
5. Сцена менять не нужно — она строит меши из готовых деталей.

Размеры — в миллиметрах, модель строится в метрах (`MM = 0.001`).
Ошибки валидации — списки строк по-русски (их показывает оператор, а на этапе 4
они пойдут ИИ на повтор).

## Библиотека (этап 5)

Экран **«Библиотека»** (кнопка в шапке): вкладки **Декоры / Фурнитура / Примеры**.
- Декоры: 7 встроенных + свои (название, фото, цвет). Свои попадают в свотчи
  корпуса/фасадов редактора и в экспорт только если используются в проекте.
- Ручки: 5 стандартных (Планка 96/160/320, Кнопка, Торцевая) + свои по фото/тексту.
  Выбор ручки — в параметрах предмета, длина влияет на 3D-геометрию.
- Примеры цеха: фото/эскизы готовых работ с заметками. До 5 примеров подаются
  ИИ как контекст стиля.

Хранение: `data/library/` (не в git). Фото — JPG/PNG/WebP до 5 МБ.

## ИИ (этап 4, текст)

В панели **«ИИ-чат»** вводятся endpoint, модель и API-ключ
(OpenAI-совместимый API, например OpenAI или OpenRouter). Ключ хранится
только в `data/settings.json`, в браузер отдаётся маска. Кнопка
**«Проверить»** делает крошечный пробный запрос.

- **«Собрать из описания»** — проект из текста,
- **«3 варианта»** — три проекта на выбор,
- **«Поправить»** — правит текущий проект по текстовой правке.

Ответ ИИ проверяется по схеме; кривой ответ не ломает приложение
(один авто-повтор с описанием ошибок, затем понятное сообщение).
Если данных не хватает, ИИ возвращает уточняющие вопросы.
Лог вызовов — в `data/ai_logs.jsonl`, без ключа. Правила цеха для ИИ —
в `app/ai_rules.md`. Применение варианта — через **«Применить»**.

Ограничения (бэклог в `docs/HISTORY.md`): вход только текстовый
(фото эскиза/комнаты — будущий шаг), угловая кухня и новые типы мебели —
этап 6, ИИ отвечает на такой запрос вопросом. До 5 примеров из
«Библиотеки → Примеры» подставляются в промпт как контекст стиля.
откат — **Ctrl+Z**.

## Экспорт для клиента (этап 3)

В редакторе — панель **«Экспорт для клиента»**: деталировка, цвета,
комната, цена, пароль. Кнопка **«Создать HTML для клиента»** собирает один
автономный файл `<id>-client.html` (three.js + генераторы + JSON проекта
внутри, ~1.5 МБ, без ссылок на сервер). Файл скачивается и сохраняется
в `data/<id>/exports/`, его можно открыть через
`GET /api/projects/<id>/export/preview` для проверки.

Публикация вручную: перетащите файл на [Netlify Drop](https://app.netlify.com/drop)
или Cloudflare Pages и отправьте полученную ссылку владельцу цеха.
Пароль — простая клиентская защита, не полноценная безопасность.

## Тесты

```
.venv\Scripts\python.exe -m pytest tests -q     # валидация + хранение + экспорт + ИИ + библиотека
node tests\test_generators.mjs                  # генераторы = прототип
node tests\test_room.mjs                        # спецификация комнаты
```

## Правила

- Формулы конструкции — только в `generators/`; сцена ничего не считает.
- Цена — заглушка: поле `price` в проекте, без расчётов до прайса цеха.
- three.js — локально, без CDN и сборки. Размеры в мм, `id` проекта = имя папки.
- Полный список требований и этапов — в `TZ_mebel3d.md`.
