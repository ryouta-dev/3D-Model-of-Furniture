# ТЗ: «Мебель 3D», локальный конструктор 3D-презентаций корпусной мебели

Документ для ИИ-агента-разработчика. Читай целиком перед началом работы.

## 1. Контекст и цель

Заказчик (далее «Оператор») раньше работал в мебельном цехе. Владелец цеха делает замер у клиента и присылает Оператору размеры, примерную планировку и пожелания. Оператор делает красивую 3D-презентацию мебели, показывает владельцу, а владелец показывает её клиенту. Клиент должен в полной мере понять, что он получит.

Цель проекта: локальное приложение на ПК Оператора, куда он закидывает вводные данные (цифры, эскиз, фото комнаты, образцы декоров) и получает реалистичную интерактивную 3D-модель мебели. Модель экспортируется в отдельную ссылку для каждого клиента.

Цена в первой версии не считается. Оставить только место под неё (см. п. 11).

## 2. Пользователи и сценарий

- **Оператор** (единственный пользователь приложения): 19 лет, студент, работает с ИИ, читает базовый код, писал Telegram-ботов на Python. Интерфейс на русском, без технических терминов там, где можно.
- **Владелец цеха** и **клиент** смотрят только готовую ссылку на телефоне или ПК. Приложение они не запускают.

Основной сценарий:
1. Оператор создаёт проект, вводит размеры и пожелания (формой, текстом, эскизом, фото комнаты).
2. ИИ превращает вводные в параметры мебели (JSON), приложение строит 3D-модель.
3. Оператор правит вручную или просит ИИ сделать варианты и поправки.
4. Оператор экспортирует проект в одну ссылку и отправляет владельцу.

## 3. Решения, уже принятые с Оператором

- Приложение локальное, запускается на ПК (Windows). Первый вариант: локальный сайт, запуск файлом `start.bat`, открывается в браузере на `localhost`. Упаковка в Electron/Tauri возможна позже, архитектуру не усложнять ради неё.
- ИИ подключается через API-ключ, который Оператор вводит в настройках. Ключ хранится только локально.
- ИИ **не рисует 3D-модель сам**. ИИ возвращает параметры мебели в строгом JSON, а модель строит наш параметрический код. Так размеры точные и результат стабильный.
- Единицы: миллиметры. Язык интерфейса: русский.
- Ссылка на клиента: каждый проект экспортируется как автономная страница (HTML-файл), которую Оператор заливает на бесплатный хостинг.

## 4. Технологии

- Бэкенд: Python 3.11+, FastAPI, хранение проектов и библиотеки в папке на диске (JSON-файлы и картинки), SQLite допустима для индекса. Зависимости минимальные, установка одной командой в `start.bat`.
- Фронтенд: HTML + JavaScript (ES-модули), three.js. Без тяжёлых фреймворков. Библиотеки лежат локально в проекте, не подгружать с CDN (приложение должно работать без интернета, кроме вызовов ИИ).
- ИИ: слой-обёртка `ai_provider` с одним рабочим провайдером (Claude API, с поддержкой картинок на входе) и возможностью добавить другого. Имя модели и ключ берутся из настроек, в коде не зашивать.
- Экспорт: один HTML-файл со всем внутри (код просмотрщика, JSON проекта, текстуры в сжатом виде).

## 5. Эталонный прототип

К ТЗ приложен файл `mebel3d.html`: рабочий прототип параметрического конструктора на three.js. Он служит эталоном логики конструкции. Переиспользуй его формулы, но перепиши структуру кода в модули.

Правила конструкции из прототипа (сохранить):
- Корпус: две боковины (толщина t × высота корпуса × глубина−4), крышка и дно между боковинами, задняя стенка ХДФ 4 мм накладная.
- Толщина ДСП 16 или 18 мм. Цоколь: планка, отступ от переднего края 60 мм.
- Полки равномерно по внутренней высоте, глубина на 20 мм меньше корпуса.
- Фасады накладные, толщина как у ДСП, зазор 3 мм. Двери: 1 или 2, петли по внешним краям, открытие наружу.
- Ящики: фасад + короб (две боковины, задняя стенка, дно ХДФ 4 мм), зазор по бокам 13 мм, выезд на ~70% глубины короба.
- Ряд модулей (кухня): модули ставятся подряд, столешница 38 мм одной плитой со свесом 30 мм спереди.
- Деталировка: список деталей с размерами и количеством, площадь ДСП, ориентировочное число листов 2750×1830 мм с запасом 15%.

## 6. Формат проекта (JSON)

Проект хранится в файле `project.json`. Схема версионируется (`version`). Пример:

```json
{
  "version": 1,
  "id": "2026-11-07-aigul-kitchen",
  "name": "Кухня для Айгуль",
  "client": "Айгуль",
  "notes": "Из эскиза владельца, ручки чёрные",
  "room": {
    "enabled": true,
    "width": 3600, "depth": 3200, "height": 2700,
    "wallTexture": "paint_white", "floorTexture": "laminate_oak",
    "windows": [{ "wall": "back", "x": 800, "width": 1200, "height": 1300, "sill": 900 }],
    "panorama": null
  },
  "items": [
    {
      "id": "i1", "type": "kitchen_base",
      "position": { "x": 0, "z": 0 }, "rotationY": 0,
      "w": 600, "h": 720, "d": 560, "t": 16, "plinth": 100,
      "modules": 3, "shelves": 1, "front": "door1", "drawers": 3,
      "top": true, "lift": 0,
      "corpus": "white", "facade": "sonoma", "handle": "bar160"
    }
  ],
  "price": { "total": null, "currency": "KZT", "lines": [] }
}
```

Типы мебели (`type`): `wardrobe`, `chest`, `kitchen_base`, `kitchen_wall` (первый этап); `sliding_wardrobe`, `kitchen_corner`, `bed`, `table` (второй этап). Каждый тип реализуется отдельным модулем-генератором с общим интерфейсом: `build(params) → { threeGroup, parts[], animations[] }`.

Проект может содержать несколько предметов (`items`), например кухня из нижнего и верхнего рядов плюс шкаф в той же комнате.

## 7. Функциональные требования

### 7.1. Редактор проекта
- Список проектов: создать, открыть, дублировать, удалить, переименовать.
- Окно 3D (вращение пальцем/мышью, масштаб, сброс вида) + панели параметров, как в прототипе.
- Размерные метки на модели (ширина, высота, глубина).
- Размещение предметов в комнате: перетаскивание по полу, поворот на 90°, привязка к стенам.
- Отмена и повтор последних действий (минимум 20 шагов).
- Автосохранение.

### 7.2. Реалистичность
Цель: клиент должен ясно понимать результат. Реальное время в браузере, без требования «как фото».
- Физические материалы (PBR): текстуры дерева (цвет + шероховатость, по возможности normal map), глянец и матовость фасадов, металл ручек.
- Освещение окружения (HDRI или процедурное небо), мягкие тени, затенение углов (SSAO или аналог), тональная коррекция.
- Комната: коробка по размерам с текстурами стен и пола, плинтус, окна, дверной проём. Опционально 360°-фото как фон. Кнопка включения и выключения комнаты.
- Переключатели: день/ночь (свет), цвет фасада и корпуса, ручки, комната вкл/выкл.
- Интерактив: клик по двери или ящику открывает его с анимацией; кнопка «открыть всё»; внутри видны полки и наполнение.
- Режим презентации: плавный автооблёт с остановками на ключевых ракурсах.
- Качество графики с автопонижением на слабом телефоне клиента.

### 7.3. Вывод
- Скриншот PNG высокого разрешения.
- Видео облёта (запись канваса, WebM; конвертация в MP4 через ffmpeg, если он установлен).
- Экспорт в автономную HTML-страницу для клиента (п. 8).
- Деталировка в виде таблицы на экране и выгрузка в CSV.

### 7.4. Библиотека образцов
- Загрузка фото декоров ЛДСП/МДФ: название, фото, ориентировочный цвет. Приложение делает из фото бесшовную или обрезанную текстуру и превью.
- Загрузка готовых проектов цеха (фото, эскизы, размеры) в раздел «Примеры». Они подаются ИИ как контекст, чтобы он понимал стиль и типовые решения цеха.
- Каталог фурнитуры: типы ручек (форма, размер, цвет). Минимум 5 стандартных.
- Всё хранится в локальной папке и экспортируется вместе с проектом только в той части, которая в нём используется.

### 7.5. ИИ-модуль
Входы: текст пожеланий; фото эскиза или планировки; фото комнаты; выбранные образцы из библиотеки; текущий JSON проекта.
Выход: только JSON по схеме п. 6 (допустимо несколько вариантов).
Требования:
- Ответ ИИ проходит строгую проверку по схеме. Любые числа проверяются на допустимые диапазоны (размеры, количество). При ошибке один автоматический повтор с описанием ошибки, затем понятное сообщение Оператору.
- Кнопки: «Собрать из описания», «Сделать 3 варианта», «Поправить» (например, «сделай фасады темнее», «добавь ящики»). Правки меняют текущий JSON, а не пересоздают проект.
- ИИ предлагает, Оператор подтверждает: изменения показываются перед применением, откат одной кнопкой.
- Если вводных не хватает (нет глубины, нет высоты потолка), ИИ задаёт уточняющие вопросы в чате, а не придумывает числа молча.
- В системном промпте зашиты правила цеха: допустимые размеры, стандартные глубины (кухня низ 560, верх 320, шкаф 550), толщины ДСП, зазоры. Правила лежат в редактируемом файле конфигурации.
- Вызовы ИИ логируются локально (вход, выход, время) для отладки. Ключ в логи не попадает.

### 7.6. Настройки
- Провайдер ИИ, API-ключ (показывать маской, проверка кнопкой «Проверить»), имя модели.
- Папка хранения проектов и библиотеки.
- Единицы и допуски по умолчанию (толщина ДСП, зазор, цоколь).
- Качество графики по умолчанию.

## 8. Экспорт ссылки для клиента

- Экспорт создаёт один автономный HTML-файл (или папку `index.html` + ассеты, если файл получается слишком большим). Внутри: просмотрщик, данные проекта, текстуры, настройки интерактивных кнопок. Никаких ссылок на локальный сервер, ключи ИИ и данные других проектов.
- В экспортной странице нет редактора. Есть: вращение, масштаб, открытие дверей и ящиков, переключатель цветов (только те варианты, которые Оператор разрешил), комната вкл/выкл, день/ночь, кнопка «Показать размеры».
- Оператор может скрыть любые детали из показа (например, внутреннюю деталировку).
- Публикация первой версии вручную: приложение показывает инструкцию «как залить на Netlify Drop / Cloudflare Pages» и открывает папку с файлом. Вторая версия: кнопка «Опубликовать» через API выбранного хостинга и одна уникальная ссылка на клиента.
- Опциональный пароль на страницу (простая защита на стороне клиента, честно описать в интерфейсе, что это не полноценная безопасность).
- Страница должна открываться на телефоне за разумное время: целевой размер до 15 МБ, сжатие текстур, ленивая загрузка комнаты.

## 9. Экраны интерфейса

1. **Проекты**: сетка карточек (превью, название, дата).
2. **Редактор**: слева или сверху 3D, рядом панели «Мебель», «Комната», «Материалы», «ИИ-чат», «Деталировка».
3. **Библиотека**: вкладки «Декоры», «Фурнитура», «Примеры».
4. **Экспорт**: настройки показа, предпросмотр, кнопки скриншот, видео, ссылка.
5. **Настройки**.

Интерфейс адаптируется под экран ПК, но 3D-просмотрщик для клиента работает на телефоне. Тёмная и светлая тема.

## 10. Нефункциональные требования

- Windows 10/11. Установка: распаковать папку, дважды щёлкнуть `start.bat`. Первый запуск сам ставит зависимости и сообщает о ходе.
- Работа без интернета (кроме вызовов ИИ и публикации).
- Данные пользователя лежат в отдельной папке `data/`, не в папке с кодом. Код можно обновлять без потери проектов.
- Читаемый код с комментариями по-русски там, где логика конструкции неочевидна. `README.md` на русском: запуск, структура, как добавить новый тип мебели.
- Автотесты на: генерацию деталировки для каждого типа мебели, валидацию JSON от ИИ, экспорт (файл открывается и содержит нужные данные).
- Ключи API и пути не попадают в экспорт и логи.

## 11. Цена (заглушка)

В первой версии цену не считаем. Реализовать только:
- поле `price` в проекте (`total`, `currency`, `lines[]`);
- ручной ввод итоговой цены и необязательных строк (материал, работа, доставка);
- чекбокс «Показывать цену клиенту» (по умолчанию выключен).
Автоматический расчёт по деталировке и прайсу цеха оставить на будущее, структуру данных не ломать.

## 12. Этапы и критерии приёмки

**Этап 1. Ядро.** Модульная структура, формат проекта, генераторы 4 типов мебели из прототипа, деталировка, сохранение и открытие проектов, редактор с 3D и панелями.
Приёмка: из `project.json` строится модель без ручных правок; деталировка совпадает с прототипом для того же набора параметров.

**Этап 2. Реализм и интерактив.** PBR-материалы, освещение, комната с текстурами, размещение предметов, открытие дверей и ящиков по клику, режим презентации, скриншот.
Приёмка: на модели шкафа в комнате видны мягкие тени и текстуры дерева, двери открываются кликом, скриншот сохраняется в PNG.

**Этап 3. Экспорт.** Автономная HTML-страница для клиента, разрешённые варианты цветов, ссылка через ручную публикацию, пароль по желанию.
Приёмка: файл открывается без запущенного приложения на телефоне, содержит только нужное, весит до 15 МБ.

**Этап 4. ИИ.** Провайдер, ключ в настройках, сборка проекта из текста, из эскиза и фото комнаты, три варианта, правки, валидация, лог.
Приёмка: по тексту «кухня 3 метра, нижние модули по 600, 2 двери, верх 3 модуля, дуб сонома» получается корректный проект; кривой ответ ИИ не ломает приложение.

**Этап 5. Библиотека.** Загрузка декоров и фурнитуры, примеры для ИИ, использование в проектах и в экспорте.

**Этап 6. Новые типы мебели.** Шкаф-купе, угловая кухня, кровать, стол. Каждый тип отдельным модулем с тестами деталировки.

**Этап 7. Видео и публикация.** Запись видео облёта, кнопка публикации через API хостинга.

## 13. Как работать агенту

- Начни с краткого плана этапа 1 и покажи Оператору. Дальше работай небольшими шагами, после каждого шага запускай проект и проверяй.
- Не придумывай конструктивные размеры. Если правила цеха неизвестны, возьми значения из прототипа, вынеси в конфиг и отметь в списке допущений.
- Не добавляй функции вне текущего этапа без согласования.
- После каждого этапа кратко опиши Оператору простым языком: что работает, что проверено, что осталось.
- Спрашивай Оператора, когда решение влияет на то, что увидит клиент (внешний вид, тексты на странице клиента, названия декоров).

## 14. Допущения (Оператор может изменить)

1. ПК с Windows и установленным Python 3.11+ (если нет, `start.bat` подсказывает, как поставить).
2. ИИ-провайдер: Claude API. Ключ у Оператора будет.
3. Хостинг для ссылок: Netlify Drop или Cloudflare Pages (бесплатные).
4. Валюта в заглушке цены: тенге (KZT).
5. Размеры стандартных листов: ДСП 2750×1830 мм, толщина 16 или 18 мм. Уточнить у цеха реальные листы и декоры.

## 15. Открытые вопросы к Оператору и владельцу цеха

1. Какие декоры и фурнитура самые частые у цеха (нужны фото или названия)?
2. Показывать ли клиенту деталировку, или только внешний вид?
3. Нужна ли ссылка с паролем, или достаточно непубличной ссылки?
4. Достаточно ли реального времени в браузере или нужен «как фото» рендер для части заказов?
5. Бренд цеха: название и логотип на странице клиента.
